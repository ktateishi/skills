# 文書種別ごとのセクション構成

推奨する構成。依頼の内容に合わせてセクションを分割・統合してよいが、最後は必ず「用語集」にする。セクション数は5〜15個。

## 技術解説

仕組みや設計を理解してもらうための文書。

1. 背景と目的：なぜこの仕組みがあるのか、この文書で何がわかるのか
2. 全体像：構成要素と関係を図で示す
3. 仕組みの詳細：要素や処理の流れごとに1セクションずつ（複数可）
4. 設計上の判断と制約：なぜこの形にしたのか、何を諦めたのか
5. 運用上の注意：よくある落とし穴、監視すべき点
6. 用語集

要点：この仕組みが何をするものか、中心となる考え方を書く。
よく使う部品：図、注記、コードブロック、表。

## 手順書

読み手がそのとおりに作業すれば完了できる文書。

1. 目的と対象：何ができるようになるか、誰が作業するか、所要時間
2. 前提条件：チェックリストで示す
3. 手順：ステップで示す。10ステップを超えるときは、作業のまとまりごとにセクションを分ける
4. 完了の確認：チェックリストで示す
5. トラブルシューティング：症状・原因・対処の表で示す
6. 用語集

要点：作業の目的、所要時間、作業後の状態を書く。
よく使う部品：ステップ、チェックリスト、コードブロック、注意と警告の注記。

## 提案書

読み手に判断や承認を求める文書。

1. 背景：現状と、提案に至った経緯
2. 課題：解決すべき問題と、放置した場合の影響
3. 提案内容：何をするのか。案が複数あるときは比較表で示す
4. 期待される効果：できるだけ数値で示す
5. 費用と体制
6. スケジュール
7. リスクと対策
8. 用語集

要点：提案の結論と、読み手にお願いしたい判断（承認・予算など）を書く。
よく使う部品：表（比較表）、数値カード、図。

## 報告書

実施したことや結果を共有する文書。

1. 概要：対象の期間と範囲、何を報告するのか
2. 結果：主要な数値を数値カードで示す
3. 詳細：項目ごとに1セクションずつ（複数可）
4. 課題と考察：うまくいかなかった点と、その原因
5. 今後の対応：誰が、いつまでに、何をするか
6. 用語集

要点：最も重要な結果と、それに対する評価を書く。
よく使う部品：数値カード、表、図。
